# ScreenCap

常駐在系統匣的 Windows 截圖工具，用 .NET 10 WPF 寫成。可以截圖並加上標註、把圖片貼在桌面上、錄成 GIF 或 MP4，以及辨識圖片中的文字。

## 功能

**截圖**
- 框選任意範圍，滑鼠移過時自動偵測視窗與控制項
- 放大鏡顯示游標座標與 HEX / RGB 色值，按 `C` 複製色值，按 `Shift` 切換複製的格式
- 方向鍵逐像素微調選取範圍；`Ctrl+A` 選取整個螢幕
- 按 `R` 鎖定框選比例（1:1、4:3、3:2、16:9，拖成直的就是 9:16 等），拖曳與調整大小都維持比例；點選區左上角的寬高可以直接輸入精確尺寸
- 按 `W` 截取游標下的整個視窗，被其他視窗擋住的部分也會截到；Windows 11 的圓角會保留
- 按 `,` / `.` 切換到之前截過的範圍
- 延遲截圖（3 / 5 / 10 秒），方便截下拉選單或滑鼠提示
- 可選擇把滑鼠游標也截進去

**標註**
- 矩形、橢圓、箭頭、直線、折線、量測（標出兩點間的像素距離，斜線另標寬、高與角度）、畫筆、螢光筆、序號標記、文字（可選字型，設粗體、斜體、底線、底色）、馬賽克或高斯模糊（可調強度）、對話框、放大鏡、聚光燈（框選範圍以外調暗，可調暗度）、圖章（勾、叉、星號等符號，OK、NG、已完成等文字章，或自訂圖片）
- 粗細與文字大小用滑桿調整，也能直接輸入數值，每種工具各自記住；矩形與橢圓可以填滿；線條可以改成虛線；標註可以調不透明度
- 按住 `Shift` 畫正方形、正圓、45° 箭頭、直線與量測線
- 畫好的標註在完成截圖前都能再選取、移動、調整大小、改顏色，也能複製貼上（可貼到下一張截圖）與調整上下層
- `Ctrl+Shift+F1` 再次開啟上一張截圖，標註都還能修改
- 14 種預設顏色，另有調色盤可用色塊或 HEX 色碼自訂，並記住最近用過的顏色；也能用吸管從截圖上取色
- 可以復原 / 重做

**輸出**
- 美化：把截圖放在漸層、純色或透明背景上，加上留白、圓角與陰影，截圖與外框的圓角可分別調整，可即時預覽；透明背景存成 PNG，複製時也保留透明（存 JPG / BMP 時改成白底）
- 複製到剪貼簿、另存 PNG / JPG / BMP
- `Ctrl+Shift+S` 快速存檔：不跳對話框，直接存到設定的資料夾
- 自訂檔名格式：日期、時間、視窗標題、流水號，例如 `{title}_{n}`
- 存檔後可自動複製檔案路徑，或在檔案總管中顯示檔案
- `Enter` / 雙擊的預設動作可改成快速存檔、另存或貼圖

**截圖歷史庫**
- 複製、存檔或貼到桌面的截圖自動保留一份（預設最近 100 張，可調整或關閉）
- `Ctrl+Shift+F2` 以縮圖瀏覽，再貼到桌面、複製、另存、做文字或 QR Code 辨識
- 可以搜尋視窗標題，也能搜尋截圖裡的文字（背景自動 OCR，不需要連網）

**貼圖**
- 把截圖或剪貼簿中的圖片固定在所有視窗最上層
- 可一次隱藏 / 顯示所有貼圖，並還原最近關閉的貼圖
- 剪貼簿是文字時貼成便條；是色碼（`#1E88E5`、`rgb(30, 136, 229)`）時貼成色塊
- 滾輪縮放、`Ctrl+滾輪` 調透明度、旋轉與翻轉
- 可以回到編輯器再加標註
- 滑鼠穿透：點擊會穿過貼圖，點到後面的視窗

**錄影**
- 錄下任意範圍，滑鼠游標也會錄進去
- 可以暫停 / 繼續，暫停的時間不會出現在影片中
- 可標示滑鼠點擊，並在畫面下方顯示按下的按鍵（例如 `Ctrl + C`），適合錄操作教學
- GIF：每秒 10 格，只編碼有變化的部分，畫面靜止時檔案很小
- MP4：每秒 30 格，使用 Windows 內建的 H.264 編碼器；可以錄進系統聲音（電腦正在播放的聲音）與麥克風，混成一條 AAC 音軌
- 錄完後可以先裁剪：拖曳時間軸兩端剪掉開頭與結尾，可逐格微調並播放預覽（可在設定中關閉）
- 錄影範圍的紅框和控制列不會被錄進去，控制列可以拖曳移開；存檔後檔案會同時複製到剪貼簿

**長截圖**
- 自動用滑鼠滾輪往下捲動，並把每一段拼接成一張長圖
- 網頁頂端或底部固定不動的區塊只保留一份；選取範圍內含捲軸或側邊欄也能對齊
- 完成後可以預覽、複製、另存或做文字辨識

**文字辨識（OCR）**
- 使用 Windows 內建的辨識引擎，不需要連網
- 支援中英文混合；中文字之間不會多出空格
- 辨識結果可以修改後再複製
- `Ctrl+Alt+F1` 截圖辨識文字：框選後直接把文字複製到剪貼簿，不經過編輯器

**QR Code 與條碼**
- 從截圖工具列或貼圖（`Q`）辨識 QR Code 與條碼（EAN、UPC、Code 128、Code 39、Data Matrix、PDF417、Aztec），網址可直接開啟
- 深色背景上的淺色 QR Code、很小的 QR Code 也能辨識
- `Ctrl+Alt+F2` 截圖辨識 QR Code：框選後直接把內容複製到剪貼簿

**其他**
- 淺色 / 深色模式，可設為跟隨 Windows
- 熱鍵、存檔資料夾、開機時啟動都可以在設定中調整
- 自動更新：每天檢查 GitHub 上的新版本，確認後自動下載、驗證並重新啟動
- app 內附使用說明

## 預設熱鍵

| 熱鍵 | 功能 |
|---|---|
| `F1` | 截圖 |
| `Shift+F1` | 錄影；錄影中再按一次停止 |
| `F3` | 把剪貼簿中的圖片（或文字、色碼）貼到桌面 |
| `Ctrl+Shift+F1` | 再次開啟上一張截圖 |
| `Ctrl+Shift+F2` | 開啟截圖歷史庫 |
| `Ctrl+Alt+F1` | 框選範圍，直接複製其中的文字 |
| `Ctrl+Alt+F2` | 框選範圍，直接複製其中的 QR Code 或條碼內容 |

熱鍵可以在系統匣選單的「設定」中更改。截圖畫面與貼圖上的其他快捷鍵，請看系統匣選單裡的「使用說明」。

## 系統需求

- Windows 10 2004（組建 19041）或更新版本，建議 Windows 11
- 執行：單一 exe 版不需要另外安裝；一般版需要 [.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/10.0)
- 建置：.NET 10 SDK
- 文字辨識需要 Windows 已安裝對應語言的 OCR 元件：到「設定 → 時間與語言 → 語言與地區」新增語言，例如中文（台灣）

## 建置與執行

```powershell
# 建置並執行
dotnet run --project src/ScreenCap

# 執行測試
dotnet test

# 發佈成單一 exe 到 publish 資料夾：內含 .NET，目標電腦不用另外安裝
dotnet publish src/ScreenCap -p:PublishProfile=SingleFile

# 或發佈成一般資料夾（較小，但目標電腦要有 .NET 10 Desktop Runtime）
dotnet publish src/ScreenCap -c Release -r win-x64 --self-contained false -o publish
```

單一 exe 約 190 MB，複製到任何 Windows 10 2004 以上的電腦都能直接執行。加上 `-p:EnableCompressionInSingleFile=true` 可以壓縮到約 80 MB，但啟動時要把程式解壓到記憶體，常駐時會多佔約 120 MB，所以預設不壓縮。

啟動後只會出現系統匣圖示。ScreenCap 同一時間只會執行一份，重複開啟時新的會直接結束。

> ScreenCap 執行時會鎖住 `bin` 裡的執行檔，所以重新建置前要先從系統匣結束它。如果不想關掉，可以加 `--artifacts-path <其他資料夾>`，把建置輸出放到別處。

```
  Help/          app 內的使用說明

  Native/        Win32 P/Invoke
  Barcode/       QR Code / 條碼結果視窗、截圖辨識 QR Code 熱鍵的流程
  Ocr/           文字辨識結果視窗、截圖辨識文字熱鍵的流程
  Pin/           貼圖視窗

  Services/      擷取螢幕、偵測視窗、熱鍵、剪貼簿、存檔、設定、截圖歷史、OCR、QR Code / 條碼解碼
  Settings/      設定視窗

  Update/        檢查 GitHub release、下載並取代執行檔
tests/ScreenCap.Tests/  xUnit 測試
```

## 實作說明

- **座標與 DPI**：截圖一律以實體像素處理，並以 Per-Monitor V2 DPI 感知執行，在高縮放比例下也不會模糊或偏移。
- **截圖**：用 GDI `BitBlt` 一次擷取整個虛擬螢幕（所有螢幕合起來的範圍），之後的選取與標註都在這張凍結的畫面上進行。
- **美化**：在 WPF 的 `DrawingVisual` 上畫背景、模糊過的圓角矩形當陰影，再以圓角裁切畫上截圖，最後用 `RenderTargetBitmap` 輸出；截圖以最近鄰插值 1:1 繪製，不會變模糊。留白、圓角與陰影以 DIP 設定再乘上螢幕縮放比例，在高 DPI 螢幕上看起來一樣大。預覽先把截圖縮小到 480 像素再套用，拖滑桿時也不會卡。有透明像素的圖片複製時同時放 PNG 格式（Office、瀏覽器、聊天軟體會讀）與白底的點陣圖（給不支援透明的程式）。
- **截取被擋住的視窗**：按 `W` 時用 `PrintWindow`（`PW_RENDERFULLCONTENT`，Chromium、DirectX 與 UWP 視窗也畫得出來）請視窗把自己畫進點陣圖，裁掉看不見的縮放邊框後貼回凍結的畫面，再選取這個視窗，所以標註與輸出都和一般截圖一樣。`PrintWindow` 畫出的是直角，Windows 11 上會依視窗的圓角設定把四角切回圓角，邊緣與後面的畫面混色。視窗沒畫出任何內容（整張全黑）時改提示使用一般框選。
- **GIF 編碼器**：自己實作，不依賴第三方套件。每格只編碼與上一格不同的矩形範圍；每格有自己的 255 色調色盤，顏色超過時用中位切割法（median cut）減色；LZW 壓縮也是自己寫的。
- **MP4**：透過 Media Foundation 的 Sink Writer 寫檔。COM 介面直接用函式指標呼叫，不另外宣告整套介面。
- **錄音**：用 WASAPI 共用模式擷取預設播放裝置（loopback）與預設麥克風，請 Windows 轉成 48 kHz 16 位元立體聲後混音。每段聲音依錄影時鐘放到它被擷取的時間點，所以播放裝置沒有聲音時（loopback 這時完全不送資料）會留下靜音，之後的聲音仍與畫面對齊；混音比時鐘晚 150 毫秒，讓稍晚送達的資料也能放進去。暫停期間收到的聲音直接丟掉。
- **長截圖拼接**：每捲一次，等畫面連續兩次相同（捲動動畫結束）才擷取。每一行切成 16 段計算雜湊，至少 12 段相同才算同一行，用來找出這次捲動的距離；不跟著捲動的捲軸、側邊欄因此不會影響比對。頂端和底部固定不動的區塊在第一次捲動時偵測出來，只保留一份。
- **錄影裁剪**：GIF 不重新編碼，直接複製保留範圍內每一格的原始資料；只有第一格要換掉，因為它只記錄與前一格的差異，所以把到那一格為止的畫面合成出來，編成完整的一格。MP4 的 H.264 每一格都依賴前面的畫面，無法直接切開，所以用 Media Foundation 的 Source Reader 解碼保留的部分，再交給錄影用的同一個編碼器重新編碼，聲音也解碼成 PCM，切在保留範圍的取樣上，和畫面交錯寫回。預覽縮圖最多 300 張、最長邊 480 像素，長時間的錄影也不會佔用太多記憶體。
- **錄影擷取**：Windows 11 上用 Windows.Graphics.Capture：DWM 把每一格畫面以 GPU 材質交給程式，只把錄影範圍那一塊複製回記憶體；在 1920×1080 全螢幕下抓一格約 7 毫秒，GDI `BitBlt` 約 29 毫秒（每秒 30 格時每格只有 33 毫秒）。畫面沒變時 DWM 不送新的一格，就沿用上一格。抓回來的像素寫進 DIB，所以游標、點擊標示與按鍵仍用原本的 GDI 程式畫上去。錄影範圍跨越多個螢幕，或在 Windows 10 上（無法關閉擷取時螢幕周圍的黃框）時，改用 `BitBlt`；第一格還沒送到前也先用 `BitBlt` 補上。錄影的紅框與控制列設了 `WDA_EXCLUDEFROMCAPTURE`，兩種方式都不會錄進去。
- **錄影暫停**：暫停時停止擷取並停住錄影時鐘，繼續後時間戳記接著往下算，所以影片裡不會有一段停住的畫面。
- **QR Code / 條碼**：用 [ZXing.Net](https://github.com/micjahn/ZXing.Net) 解碼（專案唯一的第三方套件）。只找常見的格式，避免把文字或條紋誤判成少見的一維條碼；範圍不大又沒找到時，會用最近鄰插值放大 3 倍再找一次，因為螢幕上的小 QR Code 常常每格只有 1、2 個像素。沒有標示編碼的內容由 ZXing 猜測編碼，所以啟動時註冊了 CodePages 編碼。
- **截圖歷史庫**：存成 PNG 放在 `%LocalAppData%\ScreenCap\History`，在背景執行緒編碼，不會拖慢截圖。視窗標題、時間與尺寸記在同資料夾的 `index.json`；寫入時先寫暫存檔再取代，索引遺失或損壞時改從資料夾裡的 PNG 重建（只少了視窗標題）。縮圖直接以小尺寸解碼，不會把整張大圖讀進記憶體。截圖存好後在背景逐張 OCR，辨識出的文字也記在 `index.json`；搜尋時忽略空白，因為 OCR 在中文字之間加不加空格並不穩定。
- **圖章**：符號用 Segoe UI Symbol 的字形外框繪製，依外框（而不是字型的行高）置中在圓裡，所以 ? 和 ★ 也不會偏。自訂圖片縮到最長邊 512 像素後存成 PNG，放在 `%LocalAppData%\ScreenCap\Stamps`。
- **自動更新**：讀取 GitHub API 的最新 release，標籤（例如 `v1.1.0`）和 `ScreenCap.csproj` 的 `<Version>` 比較，所以發新版時兩者要一起改。下載的 `ScreenCap.exe` 先存成同資料夾的 `ScreenCap.exe.new`，比對大小與 GitHub 提供的 SHA-256。執行中的 exe 不能刪除但可以改名，所以把它改成 `ScreenCap.exe.old`、放入新檔，再以 `--updated <舊程式的 PID>` 啟動新版；新版等舊程式結束、釋放單一執行個體的 mutex 後才接手，並刪掉 `.old`。只有發佈的單一 exe 能自我更新，從原始碼執行時只會開啟下載頁面。
- **記憶體**：預設用軟體繪製（`RenderMode.SoftwareOnly`）。WPF 一用 GPU 繪製就會載入 Direct3D 與顯示卡驅動，光是開一個小視窗就多約 180 MB，對常駐系統匣的工具不划算；截圖畫面在 3840×1080 下整個重繪一次約 27 毫秒，仍然夠順。需要時可在設定中開啟 GPU 加速。另外每次截圖都有一份整個螢幕的像素，截圖、貼圖、長截圖與錄影結束約 2 秒後會做一次壓縮大型物件堆積的完整 GC，把記憶體還給 Windows，不然閒置的 app 要很久才會回收。為了 `Ctrl+Shift+F1` 保留的上一張截圖，在背景把畫面壓縮（Deflate）後才留著，重開時再解壓：3840×1080 的畫面原本要約 33 MB（像素加上點陣圖各一份），壓縮後只要幾 MB。複製圖片不用 WPF 的 `Clipboard.SetImage`：它每次另外產生的 GDI 點陣圖不會釋放，每複製一張就留下一張截圖大小的記憶體；改為自己把圖片轉成剪貼簿通用的 DIB 格式。
- **設定**：存在登錄檔 `HKCU\Software\ScreenCap`；開機時啟動寫在 `HKCU\...\CurrentVersion\Run`。
- **測試**：設定相關的測試改用另一個登錄機碼，不會動到使用者的設定。GIF 和 MP4 測試會把編碼結果解碼回來，逐像素比對，MP4 的音軌也會解碼回來檢查聲音出現的時間；錄影測試會實際擷取螢幕，所以需要在已登入的桌面環境下執行。
